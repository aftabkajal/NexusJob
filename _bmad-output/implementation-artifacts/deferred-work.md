- source_spec: `spec-1-3b-ii-frontend-sign-in-surface.md`
  summary: A non-`401` failure of `GET /api/auth/me` on load (5xx, network error, 403) leaves a signed-in user on the anonymous shell with no automatic recovery — `useSession` has `retry: false` and `staleTime: Infinity`, so nothing refetches until the key is invalidated or the page is reloaded.
  evidence: Raised by code-review pass 1 (blind-hunter, edge-case-hunter) on 1.3b-ii. - source_spec: `spec-2-2a-detail-endpoint-and-contracts.md`
  summary: The Host registers `AddProblemDetails()` but no `UseExceptionHandler`, so an unhandled exception from any endpoint handler (a transient Npgsql error mid-query, an `IIdentityApi` failure) returns a bare HTTP 500 with no RFC 9457 `application/problem+json` body — despite AD-15 requiring ProblemDetails on every non-2xx.
  evidence: Raised by code-review pass 1 (edge-case-hunter) on 2.2a. Pre-existing and app-wide — `CreateJobPostingHandler` (2.1a) and every Identity handler have the same exposure; 2.1a's Design Notes explicitly accept "a `SaveChanges` failure is a genuine 500". Deliberate error responses already use `Results.Problem` (so they are RFC 9457); only the unhandled-exception path is bare. Fix: add `app.UseExceptionHandler()` (it composes with `AddProblemDetails()` to emit a problem+json 500) early in the Host pipeline, plus a test that a forced handler exception yields `application/problem+json`. Touches `NexusJob.Host/Program.cs`, which 2.2a's "Never" list excluded, so it belongs in its own change.
