- (decision) Source scan: PRD (prd-NexusJobBmad-2026-09-05/prd.md) confirmed as UX input; Product Brief not selected as a source for this UX pass.
- (decision) Stakes: consumer-grade (full accessibility floor, real polish investment) despite PRD framing this as a practice/learning project.
- (decision) UI system: from scratch \u2014 no inherited framework tokens; DESIGN.md defines its own color/type/spacing/radius tokens.
- (decision) IA shape: one shared shell/nav, role-aware content and actions based on Company vs Job Seeker sign-in \u2014 not two distinct app shells.
- (assumption) Form factor: web only (per PRD NFR), responsive not required \u2014 treating as desktop-first single web app unless user says otherwise.
- (decision) Brand name: NexusJob is final branding, used throughout UI (logo/wordmark/voice).
- (decision) Brand register: confident & modern \u2014 bold type, high contrast, a bit of edge; reads as a sharp new tool, not a legacy HR system.
- (decision) Voice/tone: formal/professional microcopy (e.g. 'Your job posting has been published.') \u2014 corporate-adjacent register, paired with a confident/modern visual register.
- (decision) Dark mode: light-only for v1, no dark palette.
- (decision) Density: comfortable/editorial \u2014 generous whitespace, card-based listing/applicant views over dense tables.
- (decision) Motion: subtle purposeful transitions only (fade/slide on state change), no decorative animation.
- (decision) Auth entry: single sign-up/login screen with a Company/Job Seeker role toggle at top, not two separate entry paths.
- (decision) Apply gate: unauthenticated Apply click opens an inline auth gate (modal/interstitial) that returns the user to the same posting to complete applying \u2014 not a full-page redirect.
- (decision) Surface set closed: Home/search landing, Search results, Job posting detail (w/ inline apply-gate), Sign up/Log in (role toggle), Post-a-Job form, My Postings + Applicants view (Company), plus a new My Applications list surface for Job Seekers (postings applied to, no status tracking).
- (decision) Accessibility floor: WCAG 2.1 AA \u2014 contrast ratios, keyboard nav, focus states, semantic markup, form labeling/errors.
- (decision) Key flow UJ-1 (Raj/Company): sign up via role-toggle auth -> Post-a-Job form -> instant live posting -> later returns to My Postings -> Applicants list (climax: seeing real applicants).
- (decision) Key flow UJ-2 (Amara/Job Seeker): search (no auth) -> posting detail -> Apply click triggers inline auth gate -> signs up -> application auto-submits on account creation (no second Apply click) -> confirmation -> visible later in My Applications.
- (decision) Color theme: Nexus Indigo selected from color-themes-1.html \u2014 primary #23215E (deep indigo), accent #0EA5C4 (electric cyan), sharp tech-forward cool-edge register.
- (decision) Typography: modern grotesque, all-sans (Inter/Sohne-style) for both headings and body \u2014 no serif accent, no separate display cut.
- (event) Reviewer Gate offered at Finalize; user opted to skip validation and proceed to key-screen mocks.
- (decision) Resolved PRD Open Question #2: sign-up collects a name field for BOTH roles \u2014 Company sign-up collects a company/display name, Job Seeker sign-up collects a full name, both required.
