- (decision) Product name: NexusJob (NexusJobBmad is repo/tooling name only). Two-sided job platform: companies post jobs, seekers search/view/apply. Web-only.
- (decision) Real purpose is NOT resume/portfolio display - user is using this project to learn AI-based spec-driven development workflow for future use. Stack (dotnet + React) and clean architecture are the practice target, not a hiring artifact. Lowers need for market-rigor/moat sections.
- (decision) v1 scope confirmed minimal: post job, search jobs, view job details, apply to job. Company can view list of applicants (implicit requirement for apply to be meaningful). Basic auth/accounts for both company and seeker roles.
- (decision) Architecture accepted from prior research (_bmad-output/planning-artifacts/research/technical-ddd-net-react-clean-architecture-modular-2026-09-05/research.md): backend modular monolith, one module per DDD bounded context, compiler-enforced Contracts-only boundaries, Vertical Slice Architecture inside modules (full Clean Architecture reserved for genuinely complex modules). Frontend: Feature-Sliced Design mirroring bounded contexts - explicitly flagged in research as an unvalidated hypothesis to test, not proven.
- (assumption) Assumed: basic company/seeker auth required for core loop; assumed: minimal applicant-list view for companies (not full ATS); no timeline/deadline (open-ended learning project).
- (event) Fast-path draft of brief.md and addendum.md produced and presented to user for review.
